# Proposal

## Why

主线「简历押题 → 开始面试」的第二环节缺失：用户押完题后只能对着静态列表看，无法进入一问一答的模拟面试。补齐面试会话能力，让押题结果真正"练起来"。

## What Changes

- 新增面试会话能力：从押题记录发起面试，题目按押题列表顺序逐题提出，一问一答
- 问答交互：用户对当前题目提交回答（打字），系统记录完整会话（问题、回答、顺序、时间戳），随后进入下一题；全部答完会话结束
- 跳过本题：面试中可跳过当前题目（标记为已跳过、不产生回答、不可撤销），题号推进到下一题
- 语音作答为「转写填入输入框 + 用户手动确认提交」，不自动发送
- 语音作答：浏览器端语音识别（Web Speech API）将语音转为文字填入输入框；浏览器不支持或识别失败时自动回退打字作答（符合约束「ASR 失败须有回退路径」，且无音频存储与后端 ASR 成本）
- 断线恢复：会话状态持久化，进行中的会话可随时离开、重新进入后继续未完成的题目
- 会话管理：列表（进行中/已完成）、放弃会话；访问控制仅本人可见
- 「开始面试」页由占位改为可用：发起面试、进行面试、恢复会话

明确排除（后续变更）：面试评分与参考答案报告（`interview-report`）、AI 根据回答的动态追问、历史回看页面改造（`user-history`）。

## Capabilities

### New Capabilities

- `interview-session`：一问一答面试会话（发起、作答、语音回退、持久化与恢复、结束/放弃、访问控制）

### Modified Capabilities

无。押题行为不变（面试消费其产物）；导航五项不变（「开始面试」按 app-shell 预留由占位转真实功能）。

## Impact

- 后端：新增 `interviews`、`interview_messages` 表与迁移；新增 `interviews` 端点组（发起/列表/详情/提交回答/结束）；面试题目来源为押题题目（不调用大模型，确定性推进；动态追问与评分属 `interview-report` 后续变更）
- 前端：`src/views/InterviewView.vue` 由占位改造（发起入口、面试进行页：当前题目 + 打字/语音作答 + 进度、恢复入口）；`src/api/interview.ts`
- 语音：浏览器 Web Speech API（Chrome/Edge 支持 zh-CN），零后端成本；不支持的环境隐藏语音按钮
- 契约文档：`docs/api.md` 追加面试会话部分
