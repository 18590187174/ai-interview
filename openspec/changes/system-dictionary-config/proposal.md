# Proposal

## Why

押题向导中「目标岗位」「编程语言」的下拉选项此前硬编码在前端，调整选项需要改代码发版；业务上岗位与语言会随招聘市场变化，应由可维护的字典配置驱动，而不是写死。

## What Changes

- 新增字典能力：平台级字典项（类型 + 名称 + 存储值 + 排序 + 启用），首批支持 `target_role`（目标岗位）与 `programming_language`（编程语言）两种类型，类型采用白名单校验
- 新增字典端点：按类型读取启用项、读取全部、新增（同类型下存储值唯一，重复返回 409）、删除
- 新增「设置」页面（`/settings`）：分标签页维护两类字典项（增删）；入口置于顶栏用户区齿轮图标，**不进入主导航**——`app-shell` 规格已固定导航为五项，设置属于次级页面
- 押题向导的「目标岗位」「编程语言」选项改为从字典接口拉取；字典为空或接口异常时回退到前端内置默认选项，下拉仍支持手动输入新值（allow-create）

补充说明：本变更的代码已先行实现（未走提案流程，属流程违规），本提案为**事后补齐**的规格文档，如实描述当前行为，供评审确认或提出修正。

## Capabilities

### New Capabilities

- `system-dictionary`：平台级字典配置（类型白名单、读取、增删）及其在押题向导中的消费约定

### Modified Capabilities

无。押题向导的必填校验与提交行为不变（`question-prediction` 的需求未变）；导航五项结构不变（`app-shell` 的需求未变）。

## Impact

- 后端：新增 `dict_items` 表与迁移 `11a99ce2b536`；新增 `dictionaries` 端点组；`ErrorCode` 新增 `DICT_ITEM_EXISTS`
- 前端：新增 `SettingsView` 页面与 `/settings` 路由、`api/dictionary.ts`、顶栏设置入口；`ResumeQuizView` 选项来源改为字典（带回退）
- 权限：当前系统无角色体系，字典为平台级配置，登录用户即可读写；将来引入角色时需收紧写权限（记录于 design 的开放问题）
- 契约文档：`docs/api.md` 已追加字典部分
