# Design

## Context

押题向导（`question-prediction`）已实现，岗位与语言选项硬编码在前端。平台无角色体系，所有登录用户权限等同。本变更代码已先行实现，本文档如实记录关键取舍，供评审与后续演进参考。

## Goals / Non-Goals

Goals:

- 岗位与语言的选项可配置化：读取、新增、删除
- 押题向导选项字典化 + 空字典/异常回退，保证押题流程永不因字典故障而阻塞

Non-Goals:

- 字典项的编辑与启用/禁用切换（当前只有增删；字段已预留 `enabled` 与 `sort_order`）
- 多租户/按用户隔离的字典（当前为平台级共享）
- 管理员角色与权限体系

## Decisions

### 0. 默认选项随迁移预置

默认岗位/语言选项以独立迁移预置入库（而非前端硬编码兜底），保证设置页与押题向导所见一致。迁移逐项检查存在性后再插入：不覆盖用户已配置项、重复执行幂等。前端内置选项仅保留为接口异常时的运行时兜底。

### 1. 类型白名单而非开放字典表

`type` 限定 `target_role` / `programming_language`，服务端校验。防止字典表被塞入任意键值导致语义漂移；新增类型属于代码变更（伴随消费方实现）。

备选：完全开放的「键值对字典」。拒绝理由：前端无法为未知类型提供回退与渲染策略。

### 2. 平台级共享，登录用户即可写

当前无角色体系，为避免引入半套权限，写权限开放给所有登录用户。数据为平台级共享（无 owner 字段）。

备选：仅管理员可写。拒绝理由：需要先落地角色体系（独立变更）。

### 3. 存储值唯一约束放在数据库层

`(type, value)` 唯一索引 + 服务端显式查重返回 409 `DICT_ITEM_EXISTS`。数据库约束兜底并发写入。

### 4. 物理删除而非停用

`enabled` 字段已建模但读取接口只返回启用项，当前删除为物理删除。模型层面保留软删除的演进空间（启用/禁用切换留待需要时以小变更补充端点）。

### 5. 前端回退策略

押题向导挂载时拉取字典；非空则以字典为准，为空或请求失败时静默回退到内置默认选项。不使用骨架屏或错误提示打断押题主流程——字典是增强项而非依赖项。

## Risks / Trade-offs

- [任何登录用户可改动平台字典，存在误删互扰] → 当前为单团队场景可接受；引入角色体系后收紧
- [删除被押题历史引用的字典项不影响历史快照] → 押题记录保存的是目标信息快照（文本），不依赖字典存活
- [类型白名单新增需要改代码] → 每个新类型都伴随前端消费逻辑，属合理耦合

## Open Questions

- 是否需要「一键预填默认选项」的引导（当前空字典回退内置项，用户可能不知道要去设置页配置）
- 字典项是否需要排序编辑能力（当前按创建顺序 + sort_order 字段预留）
